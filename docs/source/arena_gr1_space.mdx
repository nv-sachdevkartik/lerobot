# NVIDIA IsaacLab Arena & LeRobot

Evaluate a policy that opens a microwave with the Fourier GR1 humanoid. IsaacLab Arena runs the robot, kitchen scene and wrist controller in Isaac Sim. LeRobot runs the policy in a second Python environment and connects to the simulator through [EnvHub](./envhub).

![GR1 opening the microwave in the Arena kitchen](https://huggingface.co/nvidia/isaaclab-arena-envs/resolve/489d48af6f39196f07de9a87e7d42ce922e45545/assets/Gr1OpenMicrowaveEnvironment.png)

## Installation

You need a Linux machine with an RTX GPU, a driver compatible with Isaac Sim 6.2, Docker with NVIDIA GPU support, Git LFS, and `uv`. The environment is distributed through a [private Hugging Face Space](https://huggingface.co/spaces/nvkartik/isaaclab-arena-envs-v070). Sign in with a Hub account that has read access, or use a local copy of the provider as described below.

### Set up the simulator

From a new working directory, check out Arena and LeRobot. Arena's Docker script builds the simulator image with its pinned Isaac Lab submodule. The `-e` option makes the LeRobot checkout available inside the container at `$HOME/eval/lerobot`.

```bash
git clone https://github.com/isaac-sim/IsaacLab-Arena.git
git -C IsaacLab-Arena checkout 0942242d88814e1e6762571ad2e215dd2c56dc79
git -C IsaacLab-Arena -c 'url.https://github.com/.insteadOf=git@github.com:' submodule update --init

mkdir -p arena-client
git clone https://github.com/huggingface/lerobot.git arena-client/lerobot
git -C arena-client/lerobot checkout b07adcc5e3ce42c26a248236dbb3571f84c28c43
./IsaacLab-Arena/docker/run_docker.sh -n arena-gr1 -s gr1 -e "$PWD/arena-client"
```

In the container shell, install the provider requirements and the LeRobot server into Arena's Python environment.

```bash
export SPACE_ID=nvkartik/isaaclab-arena-envs-v070
export SPACE_REV=dc177ec6a75004867fda7059307e228321597852
export ARENA_ENVHUB="$SPACE_ID@$SPACE_REV"

hf download "$SPACE_ID" requirements.txt --repo-type space --revision "$SPACE_REV" --local-dir /tmp/arena-gr1
uv pip install --python /opt/isaaclab-venv/bin/python -r /tmp/arena-gr1/requirements.txt
uv pip install --python /opt/isaaclab-venv/bin/python --no-deps -e "$HOME/eval/lerobot"
```

To use a local provider, place the complete Space folder at `arena-client/provider` on the host. In the container, set `ARENA_ENVHUB="$HOME/eval/provider"`, skip the download, and install requirements from `"$HOME/eval/provider/requirements.txt"`.

### Start the environment server

Run this in the same container shell. The server uses the GR1 PINK controller and listens on the host's loopback interface.

```bash
export OMNI_KIT_ACCEPT_EULA=YES ACCEPT_EULA=Y
isaaclab.sh -p -m lerobot.scripts.lerobot_env_server \
  --envhub="$ARENA_ENVHUB" --trust_remote_code=true \
  --sim.task=gr1_open_microwave \
  --zenoh.listen_endpoints='["tcp/127.0.0.1:7448"]' \
  --max_sessions=1 --max_envs=2
```

Leave the server running. The first launch loads scene assets and compiles shaders. Start the client when the log shows `Serving envhub task 'gr1_open_microwave'`.

## Evaluating policies

| Pretrained policy                                                    | Model checkpoint                           |
| -------------------------------------------------------------------- | ------------------------------------------ |
| [SmolVLA](https://huggingface.co/nvidia/smolvla-arena-gr1-microwave) | `1fab07da0ffb6c263c9703c296745a730a6ea696` |
| [PI0.5](https://huggingface.co/nvidia/pi05-arena-gr1-microwave)      | `9cf88e758aeb86be15e0f44364cad19cede23188` |

### Evaluate SmolVLA

Open a second terminal on the host, starting in the directory where you cloned Arena. Install the policy dependencies here. Running the policy inside the Isaac Sim 6.2 environment is unsupported with its pinned Transformers version.

```bash
cd arena-client/lerobot
uv sync --locked --extra smolvla --extra dataset --extra evaluation --extra remote
source .venv/bin/activate
export SPACE_ID=nvkartik/isaaclab-arena-envs-v070
export SPACE_REV=dc177ec6a75004867fda7059307e228321597852
export ARENA_ENVHUB="$SPACE_ID@$SPACE_REV"
```

For a local provider, set `ARENA_ENVHUB` to the same absolute path you passed to the server (including its container username). Run one episode with the pretrained checkpoint. The camera rename connects Arena's RGB stream to the image input used during training.

```bash
lerobot-eval \
  --policy.path=nvidia/smolvla-arena-gr1-microwave \
  --policy.pretrained_revision=1fab07da0ffb6c263c9703c296745a730a6ea696 \
  --policy.device=cuda \
  --env.type=envhub --env.hub_path="$ARENA_ENVHUB" \
  --env.task=gr1_open_microwave --env.server.endpoint=tcp/127.0.0.1:7448 \
  --rename_map='{"observation.images.robot_pov_cam_rgb":"observation.images.robot_pov_cam"}' \
  --eval.batch_size=1 --eval.n_episodes=1 --eval.use_async_envs=false \
  --seed=42 --output_dir=outputs/arena-smolvla
```

Open `outputs/arena-smolvla/videos/gr1_open_microwave_0/eval_episode_0.mp4` to see the robot's view. The episode outcome is in `outputs/arena-smolvla/eval_info.json`. For two simultaneous episodes, set both `--eval.batch_size` and `--eval.n_episodes` to `2` and choose a fresh output directory. Arena batches the simulations on the GPU.

### Evaluate PI0.5

In the client shell, install the additional policy dependencies and make sure your Hub account can read the PaliGemma tokenizer used by the checkpoint.

```bash
uv sync --locked --extra smolvla --extra pi --extra dataset --extra evaluation --extra remote
```

Use the same evaluation command with `--policy.path=nvidia/pi05-arena-gr1-microwave`, `--policy.pretrained_revision=9cf88e758aeb86be15e0f44364cad19cede23188`, and `--output_dir=outputs/arena-pi05`. Keep the camera rename. The first action can take several minutes while the policy compiles. When you finish evaluating, stop the server with Ctrl+C.

## Explore other Arena tasks

Open the [Arena task catalog](https://huggingface.co/spaces/nvkartik/isaaclab-arena-envs-v070) and select a Python environment or YAML task. **Task source** opens the exact Arena definition. For tasks with **Open 3D view**, drag to orbit, scroll to zoom, and select a body to inspect or pose a joint. Running a policy uses the native Arena environment on the GPU.

Under **Run this task**, use **EnvHub server** to start the selected environment, then **Policy inference** in the LeRobot client. **Native scene** opens the same server with the Isaac Sim viewport on a machine with a display. For example, Franka lift uses `--envhub="$ARENA_ENVHUB:franka.py" --sim.task=lift_object`. Use the same task and provider on the client. A seeded random run checks whether LeRobot can send actions and receive observations for that task.

For a YAML task, select the catalog entrypoint on both sides. For example, the clutter task below uses Franka IK at 15 Hz. Start the server in the Arena container.

```bash
export TASK=clutter/franka_three_hammers_and_clamp_no_task
isaaclab.sh -p -m lerobot.scripts.lerobot_env_server \
  --envhub="$ARENA_ENVHUB:catalog_env.py" --trust_remote_code=true --sim.task="$TASK" \
  --sim.robot_type=franka_ik --sim.control_mode=delta --sim.fps=15 \
  --zenoh.listen_endpoints='["tcp/127.0.0.1:7448"]' --max_sessions=1 --max_envs=1
```

In the client shell, set `SPACE_ID`, `SPACE_REV`, `ARENA_ENVHUB` and `TASK` to the same values. Install the Space’s random policy and read the action width from the server.

```bash
SNAPSHOT=$(hf download "$SPACE_ID" --repo-type space --revision "$SPACE_REV" --include 'random_policy/*')
uv pip install --python "$(command -v python)" --no-deps "$SNAPSHOT/random_policy"
export ENDPOINT=tcp/127.0.0.1:7448
WIDTH=$(python "$SNAPSHOT/random_policy/describe_action.py" --endpoint "$ENDPOINT" --task "$TASK")
lerobot-eval \
  --policy.type=arena_random --policy.action_dim="$WIDTH" --policy.device=cpu \
  --env.type=envhub --env.hub_path="$ARENA_ENVHUB:catalog_env.py" --env.task="$TASK" \
  --env.server.endpoint="$ENDPOINT" --eval.n_episodes=1 --eval.batch_size=1 \
  --eval.use_async_envs=false --eval.max_episode_steps=3 --seed=43
```

## Environment configuration

| Setting | GR1 microwave task                                                                                                               |
| ------- | -------------------------------------------------------------------------------------------------------------------------------- |
| Task    | `gr1_open_microwave`                                                                                                             |
| State   | 54 joint positions in radians, plus eight auxiliary observation tensors                                                          |
| Action  | Left and right wrist positions in metres and `wxyz` orientations, followed by 22 hand joint targets in radians (36 values total) |
| Camera  | `robot_pov_cam_rgb`, 512×512 RGB                                                                                                 |
| Episode | Up to 250 control steps at 50 Hz. Opening the door ends the episode early.                                                       |

For training data, see the [Arena GR1 manipulation dataset](https://huggingface.co/datasets/nvidia/Arena-GR1-Manipulation-Task-v3). Check that your checkpoint uses the same wrist and hand action layout before evaluating it.

## Troubleshooting

- **The Space download returns 401 or 404.** Check that the Hub account used by the simulator can open the private Space and that the revision belongs to the Space. For a local copy, copy the entire Space snapshot, including the shared provider modules.
- **The client cannot connect.** Wait for the server's task-ready message and check that its listening port matches `--env.server.endpoint`. The example runs both processes on the same host.
- **A change of Space revision has no effect.** Restart the server so it imports the provider and its helper from the new revision.

For the older `--env.type=isaaclab_arena` configuration on Isaac Sim 5.1, see the [legacy Arena tutorial](./envhub_isaaclab_arena).
